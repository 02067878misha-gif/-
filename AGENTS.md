# Сохранение версий

Пользователь просит сохранять работу в GitHub и делать резервную копию каждой новой версии.

- Используйте существующий checkout. Для обычной работы не создавайте дополнительные worktree.
- При выпуске изменённой программы увеличивайте `const version` в `main.go` и видимую версию интерфейса. Идентификатор алгоритма генерации меняйте только при изменении генерируемых данных.
- Проверяйте приложение, затем коммитьте исходники. Выпускайте резервную копию командой `python scripts/backup_version.py --push` (путь к официальному Go при необходимости задаётся через `--go`).
- Каждый выпуск должен иметь отдельный каталог `backups/vX.Y.Z/`, ZIP с EXE, исходниками и примерами, SHA-256 и аннотированную Git-метку `vX.Y.Z`.
- Не перезаписывайте и не удаляйте опубликованные архивы, метки и релизы. Исправления выпускайте с новым номером версии. Не используйте force push.
- GitHub Actions проверяет каждый push в main и создаёт недостающий backup новой версии; архивы также публикуются в Releases при доступности GitHub Actions и API.
- Успешный push проверяйте по удалённым refs. Сохранение файла workflow не доказывает, что GitHub Actions уже выполнился: это проверяется отдельно.
