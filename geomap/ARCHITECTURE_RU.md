# Геологический картограф v12 — структура проекта

Это **рефакторинг исходника v12**, а не новая модель. Формулы и алгоритмы генерации не менялись.
Приложение по-прежнему работает автономно: `Go` запускает локальный сервер,
а браузер выполняет JavaScript, отрисовывает SVG и печатает PDF.

## Файлы

```text
index.html                  Разметка интерфейса, без вычислительного JavaScript
styles.css                  Стили интерфейса
js/
  core.js                   Константы, состояние приложения, общие утилиты
  terrain.js                Функция relief(): высотная модель рельефа
  geology.js                generateModel(), layer(): комплексы, мощности, слои
  faults.js                 side(), undo(), laterFaultValue(): разломы
  grid.js                   makeGrid(): дискретизация модели на сетке
  contours.js               iso(): изолинии; colorRuns(): векторная заливка
  paths.js                  buildPaths(): геологические границы, изолинии, подписи
  map.js                    renderMap(), mapMarkup(): оформление и показ карты
  sections.js               renderSection(): геологический разрез
  ui.js                     Поля ввода, управление параметрами, мышь
  export.js                 currentMapForExport(), saveSVG(), savePDF()
  events.js                 Точка входа: события интерфейса и старт генерации
main.go                     Локальный HTTP-сервер и упаковка всех ресурсов в EXE
open_windows.go             Открытие браузера в Windows
open_other.go               Открытие браузера в остальных ОС
build_windows.bat           Сборка Windows EXE
package.json                Режим JS ES Modules для инструментов разработчика
README_RU.txt               Краткая инструкция
CHANGELOG_REFACTOR_RU.md     Что именно изменилось

tests/
  compare-v12.mjs           Числовые и векторные сравнения с исходным v12
  compare-ui.py             Сравнение интерфейсов, SVG и PDF в Chromium
```

## Как работает программа

1. `events.js` получает настройки и вызывает `doGenerate()` из `ui.js`.
2. `geology.js` создаёт параметрическую модель, `terrain.js` вычисляет поверхность рельефа,
   `faults.js` задаёт геометрию и смещение по разломам.
3. `grid.js` дискретизирует модель; `contours.js` строит контуры,
   `paths.js` — SVG-графику и подписи.
4. `map.js` показывает карту, `sections.js` — разрез.
5. `export.js` копирует **отображаемую** SVG-карту и сохраняет её
   в SVG либо передаёт браузеру на печать в PDF.

JavaScript использует **нативные ES Modules с явными import/export**. Все файлы
загружаются локально из EXE, без CDN и библиотек.

## Где изменять код

- Новые геологические процессы: `js/geology.js` (+ при необходимости `js/faults.js`).
- Рельеф: `js/terrain.js`.
- Разломы: `js/faults.js`.
- Изолинии / сглаживание / метки: `js/contours.js` и `js/paths.js`.
- Параметры интерфейса: `index.html`, `js/ui.js` и `js/events.js`.
- Отображение карты: `js/map.js`.
- Разрезы: `js/sections.js`.
- Экспорт: `js/export.js`.

**Важно:** если добавлять настройку, которую читают вычислительные модули,
нужно согласовать её с `core.js` и передать через параметры или общий `state`.
Выполнена модульная декомпозиция, но существующее общее состояние `state`
сохранено ради точной совместимости с v12; полностью независимые чистые
функции — возможное следующее улучшение без спешки.

## Запуск и сборка

- Готовый `GeologicalMap_refactored_v12.exe` работает в Windows x64 без установки Go.
- Чтобы запустить **из исходников**, установите Go 1.21+ и выполните `go run .`
  в каталоге проекта; программа откроет браузер на локальном адресе.
- Чтобы собрать Windows EXE, запустите `build_windows.bat`.
- Прямое двойное нажатие на `index.html` **не предназначено** для запуска:
  браузеры обычно ограничивают `import/export` из `file://`. Используйте `go run .`
  или любой локальный HTTP-сервер для разработки.

В архив не включены сторонние пакеты, `node_modules` и библиотеки Python.
Node.js и Python нужны **только при добровольном запуске проверочных скриптов**.

## Проверка эквивалентности

Распакуйте исходный v12 в отдельный каталог. Для числовой проверки:

```sh
node tests/compare-v12.mjs /путь/к/оригинальному/index.html
```

Для браузерного сравнения (требуются Python + Playwright + Chromium):

```sh
python tests/compare-ui.py /путь/к/оригинальному/index.html
```

Последняя проверка показала совпадение численных моделей, сеток,
SVG-карты, геологического разреза и содержимого экспорта PDF/SVG.


### Дополнение v16: структуры
- `js/structures.js` — единый расчёт базальной структурной поверхности для моноклинали или складчатого комплекса. К нему обращаются `geology.js` и `faults.js`, что обеспечивает согласованность границ, разломов и поверхностей несогласия.
- В `js/core.js` конфигурация комплекса теперь хранит `structureType` (`monocline` / `folding`), `foldAmplitude`, `foldWidth`, `foldStrike`.
- Проверки: `tests/folding-model.mjs`, `tests/browser-folding.py`, `tests/compare-v15-monocline.mjs` (самодостаточная эталонная выборка v15).


## v17: последовательные складчатые деформации
`js/structures.js` экспортирует `foldDisplacement()` (вертикальное смещение складчатости)
и `undoFoldForOlderRocks()` (обратное преобразование координат древних пород).
`js/geology.js` применяет обратное преобразование **после** проверки базальной
поверхности каждого молодого комплекса, если включён `foldAffectsOlder`.
`js/faults.js` в новом режиме учитывает влияние более поздней складчатости
на следы ранее существовавших разломов. Если опция не используется,
сохраняется ветка прежних вычислений v16.

## Дополнение v18 — магматизм

Файл `js/intrusions.js` содержит конфигурацию штоков, даек и силлов, генерацию самостоятельных интрузивных объектов и функцию `insideIntrusion()` для пространственной классификации. Он не рисует SVG и не зависит от DOM. Вызов `generateIntrusions(m,settings)` в `js/geology.js` выполняется после построения комплексов и разломов. `layer(x,y,z,m)` проверяет интрузивные тела в порядке от молодых к древним, учитывая уже применённые обратные преобразования разломов и наследуемой складчатости. Для каждого тела создаётся отдельный литологический код после осадочных слоёв (`m.totalUnits+1` и далее); верхнюю границу кодов хранит `m.totalMaterialUnits`.

Модули `js/paths.js`, `js/sections.js` и `js/map.js` используют эти новые коды для границ и заливки. Даже если осадочная заливка отключена, магматические тела получают цвет через `intrusionFillPath`. Панели параметров в `js/ui.js` и действия добавления/изменения/удаления в `js/events.js` не содержат геометрических формул.

## Версия v19 — структура пользовательского интерфейса
- `index.html` содержит статическую карточку общих параметров карты с тремя нативными сворачиваемыми разделами `details` и контейнер динамических карточек комплексов.
- `js/ui.js`, функция `renderComplexPanels()`, отображает карточки комплексов в элементах `details`, при ререндере восстанавливает их состояние `open`.
- `js/ui.js`, функция `doGenerate()`, после расчёта обновляет компактную сводку по комплексам/слоям/разломам/интрузиям и текст заголовков карточек.
- `styles.css` содержит дополнительный блок правил, начинающийся с комментария `v19 — panel-based editor UI`.
- Геологическая геометрия и экспорт не изменялись.

## v20: геометрия интрузивных тел

Модуль `js/intrusions.js` теперь рассчитывает:
- для штока: нормированную по площади неправильную форму поперечного сечения, апофизы, случайную шероховатость контакта и стены с подписанным наклоном;
- для дайки: конечную по простиранию наклонную пластину с выклиниванием к концам и номинальной площадью распространения;
- для силла: согласную структурную поверхность с эллиптическим контуром и уменьшающейся к краям мощностью;
- для штока/дайки с опцией деформации: обратное преобразование высотной и плановой координат относительно центра тела.

Численное поле материала формируется `geology.js/layer()` и отрисовывается общими методами `paths.js`, `map.js`, `sections.js`; каких-либо отдельных «нарисованных сверху» контуров интрузий нет.
