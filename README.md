# Сетка Вульфа — генератор заданий

Автономная программа для Windows 10/11 x64. Подбирает от 1 до 20 разных вариантов, создаёт задания и отдельные ответы преподавателя в PDF. Интерфейс на русском открывается в установленном браузере. Интернет, Python, Microsoft Office и установка программы не нужны.

В интерфейсе есть порядок построений, в комплекте — общая пошаговая памятка студенту. Условия и объяснения содержат все необходимые указания для выполнения заданий.

## Интерфейс версии 1.4

- Три раздела настроек: параметры работы, состав элементов, типы задач.
- Быстрый выбор 5/10/15/20 вариантов, кнопки увеличения и уменьшения, проверка границ 1–20.
- Справа — состав будущего комплекта, число страниц и условная схема прямого/обратного листа. Схема иллюстративная; действительные значения и построения находятся в созданных PDF.
- Кнопка создания доступна в форме и в панели состава. Во время генерации параметры блокируются, отображается состояние работы.
- Готовые файлы сгруппированы: задания и памятка — студентам, построения и таблица ответов — преподавателю.
- Код набора можно скопировать; кнопка «Восстановить настройки» подставляет параметры и код завершённого комплекта. При последующем изменении параметров прежние скачиваемые файлы остаются подписаны фактическими настройками готового набора.
- Справка по построениям открывается отдельным окном без ухода со страницы. Есть ссылки на печатную памятку.
- Поддерживаются небольшие экраны, клавиатура, заметный фокус, закрытие справки клавишей Escape. Ctrl+Enter создаёт комплект.

Данные и алгоритм `wulff-v3` совместимы с версиями 1.2 и 1.3. Цветовое оформление не меняет исходные значения и расчётные ответы.

## Запуск готовой программы

1. Распакуйте `WulffGenerator_Windows_x64_v1.4.0.zip` в обычную папку.
2. Запустите `WulffGenerator.exe`. Откроется локальный интерфейс в браузере.
3. Выберите количество вариантов, виды заданий и режим: прямые, обратные либо оба.
4. Нажмите **«Создать комплект PDF»** и скачайте файлы в разделе **«Готовые файлы»**. Там же можно открыть задания для просмотра и скачать всё одним архивом. Браузер сохраняет их в свою папку загрузок или предлагает выбрать папку, согласно своим настройкам.
5. Завершайте работу кнопкой **«Закрыть программу»**. После закрытия вкладки без этой кнопки процесс завершится через 15 минут без активности.

На компьютере должна быть настроена программа браузера по умолчанию. Программа запускает только локальный HTTP-сервис на `127.0.0.1` со случайным портом и кодом доступа, не обращается к внешним серверам и не отправляет данные в интернет. При каждом запуске используется новый адрес. Файл EXE собран без цифровой подписи.

## Что входит в комплект

| Файл | Назначение |
|---|---|
| `students.pdf` | Задания студентам: численные условия прямых задач, готовые построения обратных задач, сетки и место для ответов |
| `student_guide.pdf` | Общая памятка по построениям, 2 страницы: калька, дуги, линейность, склонение, полюсы, π-плоскость и обратная задача |
| `teacher.pdf` | Те же варианты с правильными построениями и численными ответами |
| `answers.csv` | Краткий ключ для Excel, UTF-8 с BOM, разделитель `;` |
| `settings.json` | Параметры генерации и полные расчётные ответы |
| `PRINT_README.txt` | Правила печати и условные обозначения |
| `wulff-set.zip` | Весь комплект одним архивом |

Студентам выдавайте `students.pdf` и общую памятку `student_guide.pdf`. Памятку можно скачать в интерфейсе до генерации вариантов. Она является отдельным документом и не увеличивает число листов каждого варианта. Таблица, JSON и файл преподавателя содержат ответы.

На каждом листе A4 — **одна крупная сетка диаметром 180 мм**. Все выбранные элементы наносятся **совместно на одну сетку**. Прямая задача занимает один лист с пустой сеткой и таблицей исходных данных. Обратная задача занимает второй лист: на его сетке уже нанесён **отдельный случайный набор** элементов. Значения прямой и обратной задач различаются. При обоих направлениях — **2 страницы на вариант**, **40 страниц в каждом PDF** для 20 вариантов, независимо от числа выбранных типов. Печать: **A4 → фактический размер / 100%**, без подгонки. Проверьте диаметр линейкой. В `examples/` — два демонстрационных варианта (4 страницы в каждом PDF).

## Типы заданий

- **Плоскость**: построение дуги и полюса по азимуту и углу падения; обратное определение залегания по дуге.
- **Линейный элемент**: нанесение точки по азимуту и углу погружения; обратное считывание.
- **Линейность в плоскости: склонение (rake)**: построение по плоскости, углу и указанному концу простирания (направление и точный азимут); обратное определение плоскости, линии, угла rake и конца отсчёта.
- **Крылья складки**: построение двух крыльев, определение азимута и угла погружения шарнира, построение π-плоскости, перпендикулярной ему, определение двух углов и двух возможных осевых поверхностей. В обратной задаче крылья уже нанесены.

Исходные строки Excel не копируются: программа генерирует новые значения. Шаг исходных углов — 1°, 5° или 10°. Падения плоскостей выбираются в пределах 15–75°, погружения отдельных линий — 10–70°, rake — 15–75°, с округлением диапазона к выбранному шагу. Для складок отбираются пары с острым двугранным углом 25–80° и погружением шарнира не более 65°. Так исключаются вырожденные и трудночитаемые случаи. Каждый выбранный тип задания отличается между вариантами.

## Геометрические соглашения

Используется приложенная пользователем `Wulff10sm.bmp`, встроенная как PNG без изменения геометрии. Проекция **стереографическая равноугольная (Вульфа)**, нижняя полусфера. Все элементы отмечены уникальными метками: P — плоскость, Np — её полюс; L — отдельная линия; R — плоскость для rake, Lr — линия в ней; K1/K2 — крылья; H — шарнир; π — перпендикулярная ему плоскость; A/B — её пересечения с крыльями; ОП1/ОП2 — два варианта осевой поверхности. Север сверху, восток справа; азимуты отсчитываются от севера по часовой стрелке. Азимут плоскости — **азимут падения**, линии — **азимут погружения**.

Склонение (rake) — угол в плоскости между линейностью и линией простирания. Угол откладывается **вдоль дуги большого круга от указанного конца простирания**, например «25° от СЗ (аз. 308°)» для плоскости 38°/40°. Генератор выбирает любой из двух концов; направление и точный азимут указаны в условиях и ответах. В обратном задании студент определяет угол и конец отсчёта. Диапазон 0–90°. Все элементы строятся аналитически в одной системе координат: восток, север, вниз. Радиус стереографической проекции линии `r = tan(45° − plunge/2)`.

По двум неориентированным плоскостям нельзя однозначно выбрать внутренний угол складки и осевую поверхность. Поэтому программа даёт **острый угол и его дополнение до 180°**, а также **два варианта осевой поверхности ОП1 и ОП2**. Для выбора геологической осевой поверхности нужны сведения о полярности/внутренней области складки. Это геометрическая модель симметричной складки, а не восстановление произвольной природной осевой поверхности.

Ответы в PDF и CSV округлены до 0,1°, исходные параметры и неокруглённые вычисления записаны в JSON. Поля верхнего уровня каждого варианта описывают прямую задачу, поле `inverse` — отдельную обратную задачу. В CSV направление записано отдельным столбцом. Для ручного считывания ориентир допуска — ±2°; окончательный допуск устанавливает преподаватель. Азимуты 0° и 360° эквивалентны. Для горизонтальной оси допустимы противоположные направления.

## Цвета элементов

В разделе «Что включить в работу» включите **«Разные цвета элементов»**. Для каждого построения доступны отдельный оттенок в палитре и название цвета для студентов: P, Np, L, R, Lr, K1, K2, H, π, A, B, ОП1 и ОП2. Показываются настройки выбранных типов заданий.

Можно просто вписать знакомое название, например «синий» или «красным»: оттенок подберётся автоматически. При выборе оттенка в палитре поле получает известное название либо HEX-код; его можно заменить своим названием до 12 символов. Для нестандартного названия сначала выберите соответствующий оттенок. В PDF печатается соответствие «элемент — цвет», например **«P — синий; L — красный»**, включая цвета вспомогательных построений.

В прямой задаче студент выполняет построения указанными цветами. В обратной задаче исходные элементы уже окрашены. В ключе преподавателя нужным цветом показаны дуги, точки и подписи всех элементов. На каждом листе остаётся одна сетка диаметром 180 мм. Метки, формы точек и типы линий сохраняются, поэтому элементы можно различить и на чёрно-белой распечатке.

Выключенный режим создаёт чёрно-белые построения без указаний цветов. Настройки цветов сохраняются в `settings.json` и восстанавливаются кнопкой «Восстановить настройки». Кнопка «Сбросить» возвращает исходные оттенки и выключает цветной режим. Для цветных примеров из командной строки добавьте `--colors`.

## Повторение набора

Алгоритм `wulff-v3` учитывает оба конца отсчёта rake; коды предыдущих версий дают другие значения. В пределах этой версии введите тот же **код набора**, выберите те же типы заданий, шаг, режим и количество в версии алгоритма `wulff-v3`. При увеличении количества первые варианты сохраняются. Пустой код автоматически создаёт новый набор при каждом нажатии кнопки. Код готового набора отображается рядом со ссылками и записан в PDF и JSON. `settings.json` предназначен для чтения параметров, автоматического импорта в интерфейсе нет.

## Сборка из исходников

Нужен официальный Go 1.24 или новее; использован Go 1.27.3. Один модуль PDF, зафиксированный в `go.mod` и `go.sum`. Шрифт, сетка и веб-интерфейс встраиваются внутрь EXE.

```sh
go mod download
go test ./...
go vet ./...
go build -o wulff .
./wulff
```

Windows x64 из Linux:

```sh
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags='-s -w -H=windowsgui' -o dist/WulffGenerator.exe .
```

В PowerShell из папки исходников:

```powershell
$env:GOOS = 'windows'
$env:GOARCH = 'amd64'
$env:CGO_ENABLED = '0'
go test ./...
go build -trimpath -ldflags '-s -w -H=windowsgui' -o dist/WulffGenerator.exe .
```

Генерация без интерфейса (из Linux либо через `go run .`):

```sh
./wulff --generate --count 20 --seed GEO-2026 --step 5 --mode both --tasks plane,line,rake,fold --out output
```

Папка вывода не должна содержать файлы предыдущего комплекта: CLI сохраняет их, завершаясь с ошибкой, вместо перезаписи. Для сохранения следующего набора выберите другую папку.

## Проверки

В `geometry_test.go` есть контроль примера rake 38°/40°, 25° от СЗ, обоих концов простирания и построения π-плоскости. Также есть аналитические эталоны проекции, полюсов, rake и симметричной складки, проверки принадлежности линий плоскостям и шарнира обоим крыльям, биссекторных плоскостей, повторяемости и уникальности наборов. В `server_test.go` проверяются генерация файлов, скачивание ZIP, число страниц по настройкам и обработка неверных запросов. В `colors_test.go` проверяются совместимость прежних настроек, сохранение палитры, проверка названий и оттенков и неизменность задач при смене цветов.

Проведены проверки программы в Linux, интерфейса в Chromium (включая выбор количества, схемы листов, модальную справку, копирование кода, восстановление и сброс настроек, обработку ошибок и экраны шириной 360–1440 px) и печатного комплекта из 20 вариантов: A4, сетки 180 мм, 40 страниц в каждом PDF, отсутствие текста за пределами страницы. Windows EXE собран как PE32+ x86-64 GUI; запуск непосредственно в Windows в этой среде не проверен.

## GitHub и резервные копии

Проект: https://github.com/02067878misha-gif/-. Архивы выпущенных программ сохранены в [backups](backups/README.md); исходники каждого выпуска доступны по Git-меткам `vX.Y.Z`.

Для следующего выпуска увеличьте версию в `main.go` и интерфейсе, проверьте изменения и закоммитьте исходники. Затем выполните:

```sh
python scripts/backup_version.py --push
```

При необходимости укажите официальный компилятор через `--go /путь/к/go`. Команда проверяет приложение, собирает EXE, примеры и исходный ZIP, сохраняет отдельную резервную копию с SHA-256, создаёт коммит и метку, отправляет их в GitHub. Существующие версии не заменяются. Проверить текущую копию без сборки и отправки: `python scripts/backup_version.py --verify`.

Workflow `.github/workflows/backup.yml` настроен на проверку каждого push в `main`, создание отсутствующей копии новой версии и публикацию сохранённых архивов в GitHub Releases. Выполнение зависит от доступности GitHub Actions и разрешений репозитория; результат конкретного запуска проверяется во вкладке Actions. Архивы в Git сохраняются независимо от публикации Releases.
